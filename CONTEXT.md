# ComfyPress context

## Project shape
ComfyPress is a WordPress plugin workspace for generating images through a configured ComfyUI service from Gutenberg. The plugin is under `comfy-image/`; `README.md`, `PLAN.md`, and `project.json` describe user-facing behavior and planned work. Treat those docs as evolving project records and check them against source before relying on status claims.

## Current implementation anchors
- `comfy-image/comfy-image.php`: plugin bootstrap, settings, and editor script registration/localization.
- `comfy-image/includes/endpoints.php`: `comfy-image/v1` REST routes; proxies workflow submission, status, and image retrieval/import to the configured ComfyUI base URL. Multipart upload currently returns HTTP 501.
- `comfy-image/assets/block.js`: classic WordPress-global Gutenberg block; submits a workflow, polls, and inserts an imported image.
- `comfy-image/templates/example_workflow.json`: legacy scaffold-shaped mock, not a ComfyUI API workflow; it lacks `{{prompt}}`, is not used at runtime, and is excluded from the release archive. `comfy-image/examples/flux2-klein-4b.api.json` is a repository-only, smoke-tested API-format example; it is not loaded automatically or packaged without separate approval.

## Constraints and known gaps (baseline source-checked 2026-09-28; fresh evidence dated below)
- The repository has lightweight contract harnesses at `tests/php/run.php` and `tests/js/run.js`; there is no Composer/npm build manifest or PHPUnit configuration. The latest PHP run (`php -n tests/php/run.php`) passed 104 checks and the JavaScript harness passed 38. The PHP harness stubs WordPress and ComfyUI HTTP; it does not prove live database-lock concurrency. The unreleased worktree now includes contract-tested optional seed/steps/CFG overrides; live Gutenberg and generation acceptance for those fields remains pending. A separate WordPress 6.9.4 browser happy-path test verified generation/import, native Image block insertion, and prompt restoration after reload (see `PROGRESS.md`).
- REST permission callbacks require `edit_posts` and a configured role (`editor`/`author` by default); users with `manage_options` bypass the role list but still need `edit_posts`. Image import additionally requires `upload_files`. The editor sends the localized `X-WP-Nonce`. Live WordPress 6.9.4 status-route checks verified cookie/nonce middleware; on WordPress 5.9.3/PHP 8.0.19, unauthenticated and authenticated HTTP requests returned anonymous 401 and excluded-role 403 across submit/status/fetch/upload, denied a `manage_options`-only role, verified allowed-role submit and administrator bypass (200), and denied image import without `upload_files` (403) before any mock fetch. Forced attachment-registration failure returned sanitized 500 and left no uploaded file. See `PROGRESS.md` for the full live matrix.
- Submit requires the `{{prompt}}` placeholder. The unreleased block also supports optional `seed`, `steps`, and `cfg` overrides only through matching complete-value workflow markers; server-side bounds and numeric JSON substitution are contract-tested. Blank overrides preserve configured workflow values. The 0.1.2 package is unchanged, and live Gutenberg acceptance for the new controls is pending.
- The administrator-configured ComfyUI HTTP(S) base URL may include a reverse-proxy path and target private/LAN services; embedded credentials, query strings, and fragments are rejected. Outbound redirects are disabled, and ordinary workflow payloads cannot override the destination. There is no strict host allowlist: this is an explicit trusted-administrator boundary that preserves private ComfyUI support, with SSRF risk if an administrator is compromised or misconfigures the target.
- Generation is limited to 10 requests per user in a fixed 60-second transient window anchored by the first request; later successful requests do not refresh its expiry. Updates are serialized with a MySQL/MariaDB named advisory lock scoped by database, table prefix, site, and user. Lock/storage failure fails closed. Contract tests cover window reset/remaining TTL, lock acquisition/release, and contention; a live disposable WordPress concurrency run accepted 10 of 24 simultaneous requests and denied 14, with counter readback and cleanup verified. Image import enforces a finite response size/timeout, MIME plus byte validation, path-safe metadata, and file cleanup if attachment registration fails.
- First-release scope is text-to-image through the existing block and Media Library insertion. The unreleased working tree now contains per-block seed/steps/CFG controls behind explicit markers; these are not in the 0.1.2 package and live editor/generation verification remains pending. Multipart `/upload-image` remains a permission-gated HTTP 501 stub; direct `/comfy <prompt>` execution is also deferred. Local stop cancels polling only; it does not cancel the ComfyUI job.
- The user explicitly authorized the existing `invoices-wordpress-1` WP Invoice Test container. The plugin was temporarily staged/activated with temporary settings, editor/subscriber accounts, and a draft; real HTTP REST requests verified cookie-auth nonce and role gates on the status route, with the valid editor request returning 200. Cleanup completed; a read-only check confirmed the plugin inactive, plugin directory absent, all five plugin settings absent, and no matching temporary user/draft records. This did not exercise Gutenberg/browser flow, image generation/import, or controlled failure. Three supplied editor-format workflows previously completed bounded direct `/prompt` smoke tests; those do not verify the WordPress editor/media path.
- Keep current runtime/security status grounded in code; user-modified files may not yet be reflected in committed history.
