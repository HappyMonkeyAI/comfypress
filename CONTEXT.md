# ComfyPress context

## Project shape
ComfyPress is a WordPress plugin workspace for generating images through a configured ComfyUI service from Gutenberg. The plugin is under `comfy-image/`; `README.md`, `PLAN.md`, and `project.json` describe user-facing behavior and planned work. Treat those docs as evolving project records and check them against source before relying on status claims.

## Current implementation anchors
- `comfy-image/comfy-image.php`: plugin bootstrap, settings, and editor script registration/localization.
- `comfy-image/includes/endpoints.php`: `comfy-image/v1` REST routes; proxies workflow submission, status, and image retrieval/import to the configured ComfyUI base URL. Multipart upload currently returns HTTP 501.
- `comfy-image/assets/block.js`: classic WordPress-global Gutenberg block; submits a workflow, polls, and inserts an imported image.
- `comfy-image/templates/example_workflow.json`: legacy scaffold-shaped mock, not a ComfyUI API workflow; it lacks `{{prompt}}`, is not used at runtime, and is excluded from the release archive. `comfy-image/examples/flux1-krea-dev.api.json` is a repository-only API-format starter fixture; it is not loaded automatically or packaged without separate approval.

## Constraints and known gaps (source-checked 2026-09-28)
- The repository has lightweight contract harnesses at `tests/php/run.php` and `tests/js/run.js`; there is no Composer/npm build manifest or PHPUnit configuration. The latest PHP run (`php -n tests/php/run.php`) passed 75 checks; the last recorded JavaScript run passed 18. The PHP harness stubs WordPress and ComfyUI HTTP; it does not prove live database-lock concurrency, Media Library writes, or editor behavior. Separately, a live HTTP probe against the user-authorized WordPress 6.9.4 test runtime exercised cookie-auth REST nonce and role middleware (see `PROGRESS.md`).
- REST permission callbacks require `edit_posts` and a configured role (`editor`/`author` by default); users with `manage_options` bypass the role list but still need `edit_posts`. Image import additionally requires `upload_files`. The editor sends the localized `X-WP-Nonce`. Live `GET /check-status/{prompt_id}` checks observed anonymous and missing-nonce requests return 401, invalid nonce return 403 `rest_cookie_invalid_nonce`, an allowed editor with a valid nonce return 200, and a disallowed subscriber return 403 `rest_forbidden`; submit, administrator bypass, media capability, browser login, and Gutenberg interaction were not tested.
- Submit/status handlers return bounded error objects and do not expose raw upstream bodies/headers. Submit requires a `{{prompt}}` placeholder; the editor consumes the ComfyUI prompt/history/image contract.
- The administrator-configured ComfyUI HTTP(S) base URL may include a reverse-proxy path and target private/LAN services; embedded credentials, query strings, and fragments are rejected. Outbound redirects are disabled, and ordinary workflow payloads cannot override the destination. There is no strict host allowlist: this is an explicit trusted-administrator boundary that preserves private ComfyUI support, with SSRF risk if an administrator is compromised or misconfigures the target.
- Generation is limited to 10 requests per user in a fixed 60-second transient window anchored by the first request; later successful requests do not refresh its expiry. Updates are serialized with a MySQL/MariaDB named advisory lock scoped by database, table prefix, site, and user. Lock/storage failure fails closed. Contract tests cover window reset/remaining TTL, lock acquisition/release, and contention, but live multi-worker database concurrency is unverified. Image import enforces a finite response size/timeout, MIME plus byte validation, path-safe metadata, and file cleanup if attachment registration fails.
- First-release scope is text-to-image through the existing block and Media Library insertion. Multipart `/upload-image` remains a permission-gated HTTP 501 stub; direct `/comfy <prompt>` execution and per-block seed/steps/CFG controls are deferred. Local stop cancels polling only; it does not cancel the ComfyUI job.
- The user explicitly authorized the existing `invoices-wordpress-1` WP Invoice Test container. The plugin was temporarily staged/activated with temporary settings, editor/subscriber accounts, and a draft; real HTTP REST requests verified cookie-auth nonce and role gates on the status route, with the valid editor request returning 200. Cleanup completed; a read-only check confirmed the plugin inactive, plugin directory absent, all five plugin settings absent, and no matching temporary user/draft records. This did not exercise Gutenberg/browser flow, image generation/import, or controlled failure. Three supplied editor-format workflows previously completed bounded direct `/prompt` smoke tests; those do not verify the WordPress editor/media path.
- Keep current runtime/security status grounded in code; user-modified files may not yet be reflected in committed history.
